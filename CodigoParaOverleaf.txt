\section{Diseño}

El TAD AirMilles fue implementado con el siguiente diseño:
\begin{itemize}
    \item MaxHeap de Usuarios.
\end{itemize}
Esta estructura es vital para cumplir las complejidades requeridas para la operación rankingMillas.
Como trade-off de agregar el Heap surgió un problema: Vincular a los usuarios con sus posiciones en el Heap.
Recordemos que el Heap es O(1) para obtener el máximo, pero para cualquier otro elemento es O(U).

Un primer intento para solucionar este problema consistió en agregar a cada usuario un atributo con su posicion en el Heap, logrando así ir a su posicion en O(1).

Sin embargo al momento de hacer siftUp o siftDown, operaciones necesarias para mantener el invariante de la estructura, cada vez que un usuario acumula o canjea millas, habría que modificar el índice de todos los usuarios afectados por el shift.

Por lo tanto necesitábamos poder acceder y modificar, desde la clase heap, el índice de los usuarios en O(1) para cualquier usuario. Para lograr esto, decidimos que el heap no contenga simplemente a los usuarios, sino a nodos cuyas componentes son un elemento, que en nuestro caso son los usuarios, y un ID para identificarlos.

Además, tenemos un array de posiciones, cuyos índices representan el ID del usuario, por ejemplo, posiciones[1] nos dice en qué posición del heap está el usuario con ID 1 (para esto definimos una clase Vector ya que ArrayList no te deja agregar en la posición 10 si no tenés nada en la 0 a la 9, y queremos que los IDs puedan ingresar en cualquier orden). De esta manera podemos intercambiar las posiciones en el heap de 2 usuarios en tiempo constante, así que una vez que tenemos el ID del usuario al que queremos aumentar o decrecer sus millas, acomodarlo en el heap será O(log U) en el peor caso.


\begin{itemize}
    \item ABB que guarda los handles de los Usuarios.  
\end{itemize}
El ABB está conectado con el heap via handle, y ordenado via el ID del usuario. Como tenemos un ABB y no un AVL encontrar a un usuario por ID va a ser O(U) en el peor caso, pero O(log U) en el caso promedio.
\begin{itemize}
    \item Trie de Promociones.
\end{itemize}    
Implementado en forma de arreglo. En particular tenemos nodos de longitud 256. Cada posición del nodo representa un caracter. Cuando se ingresa una nueva promoción cada caracter crea nuevos nodos iterativamente. Al finalizar el nombre de la promoción, el atributo 'Elem' pasa a contener un elemento de la clase promoción.  

Para poder eliminar promociones, de forma tal que se eliminan todos los nodos que no llevan a ninguna promoción, utilizamos el atributo cantHijos. Éste cuenta la cantidad de palabras que pasan por él. Una vez que dicho atributo nos marca 1, nos está indicando que a partir de ese momento la única promoción en ese camino del Trie es la que queremos borrar.

\begin{itemize}
    \item MasAcumulador.
    \begin{itemize}
        \item El usuario que al momento tiene más millas totales.
    \end{itemize}
    \item MasCanjeador.
    \begin{itemize}
        \item El usuario que al momento gastó más millas.
    \end{itemize}
\end{itemize}

Promocion y Usuario son clases con sus correspondientes atributos y métodos.

\section{Complejidades}

Veamos  que ese diseño nos permita cumplir con todas las complejidades requeridas para cada operación.
\begin{itemize}
    \item crearSistema en O(1) 
    \begin{itemize}
        \item Inicializar ABB O(1) 
        \item Inicializar Heap O(1) 
        \item Inicializar Trie O(1) 
        \item         agregarPromocion('NoPromo') O(7) = O(1)
        \item Total = O(1)
    \end{itemize}
    \item registrarUsuario / registrarUsuarioConReferidor en O(log U) caso promedio y O(U) peor caso
    \begin{itemize}
        \item Encolamos Usuario en el Heap O(log U)
        \item Agregamos el Handle del usuario al ABB; caso promedio O(log U), peor caso O(U)
        \item Sumarle millas al usuario referidos es O(1) ya que lo que cuesta es encontrarlo
        \item En el peor caso vamos vamos a tener que actualizar la posicion en el Heap del usuario referidor del piso al tope. Eso tiene costo de O(log U) 
        \item Costo total en promedio : O(log U) +O(log U) +O(1) + O(log U)  =  O(log U)
        \item Costo total en peor : O(log U) +O(U) +O(1) + O(log U)  = O(U)
    \end{itemize}
    \item acumularMillas en O(log U  + $|$L$|$  ) caso promedio y O(U + $|$L$|$ ) peor caso
    \begin{itemize}
        \item Encontrar la promocion en el Trie: O($|$L$|$ )
        \item Obtener la informacion de la promocion,  restar del tope si es necesario O(1)
        \item Eliminar promoción en caso de ser necesario O($|$L$|$ ) [ver eliminarPromocion]
        \item Encontrar al usuario en el ABB : caso promedio O(log U), peor caso O(U)
        \item Aumentar los atributos correspondientes al usuario O(1)
        \item Reajustar la posicion del Usuario en el Heap, de ser requerido, O(log U )
        \item Costo total en promedio: O($|$L$|$ )+ O(1) +O($|$L$|$ )+ O( U) + O(1) + O(log U) = O( log U + $|$L$|$ )
        \item Costo total en peor: O($|$L$|$ )+ O(1) +O($|$L$|$ )+ O(log U) + O(1) + O(log U) = O(U + $|$L$|$ )
    \end{itemize}
    \item canjearMillas O(log U ) caso promedio y O(U) peor caso
    \begin{itemize}
        \item Encontrar al usuario en el ABB : caso promedio O(log U), peor caso O(U)
        \item Realizar la operacion canjearMillas O(1)
        \item Caso promedio : O(log U) + O(1) = O(log U),
        \item Peor caso : O(U) +O(1) = O(U)
    \end{itemize}
    \item transferirMillas en O(log U ) caso promedio y O(U) peor caso
    \begin{itemize}
        \item Encontrar al usuario transferidor en el ABB : caso promedio O(log U), peor caso O(U)
        \item Encontrar al usuario receptor en el ABB : caso promedio O(log U), peor caso O(U)
        \item Realizar el balance correspondiente del saldo de Millas de transferidor O(1)
        \item Alterar el Heap para reflejar las nuevas millas del transferidor O(log U) en el peor caso
        \item Actualizar, si fuera necesario, MasCanjeador O(1)
        \item Realizar el balance correspondiente del saldo de Millas de receptor O(1)
        \item Alterar el Heap para reflejar las nuevas millas del receptor O(log U) en el peor caso
        \item Costo Promedio : O(log U) + O(log U) + O(1) + O(log U) + O(1) + O(1) + O(log U) = O(Log U)
        \item Costo peor : O( U) + O(U) + O(1) + O(log U) + O(1) + O(1) + O(log U) = O(U)
    \end{itemize}
    \item consultarSaldo / consultarCategoria en O(log U ) caso promedio y O(U) peor caso
    \begin{itemize}
        \item Encontrar al usuario en el ABB : caso promedio O(log U), peor caso O(U)
        \item Consutlar su saldo/Categoria O(1)
        \item Caso promedio : O(log U) + O(1) = O(log U),
        \item Peor caso : O(U) +O(1) = O(U)
    \end{itemize}
    \item iniciarPromocion / iniciarPromocionConTope en O($|$L$|$ )
    \begin{itemize}
        \item Insertar elemento en Trie O($|$L$|$ )
        \item En el peor caso por cada letra nueva hay que crear una nueva 'rama' del Trie. Eso tiene consto fijo dado por la longitud del arreglo O(256)
        \item crear Promocion con o sin tope O(1)
        \item costo total O($|$L$|$ ) + O(1) = O($|$L$|$ )
    \end{itemize}
    \item finalizarPromocion en O($|$L$|$ )
    \begin{itemize}
        \item Buscar la promocion en el Trie O($|$L$|$ )
        \item Eliminar la promocion si solamente se tiene que eliminar la promocion O(1), se se tiene que eliminar ramas O($|$L$|$ )
        \item costo total pero caso O($|$L$|$ ) + O($|$L$|$ ) = O($|$L$|$ )
    \end{itemize}
    \item elMasAcumulador / elMasCanjeador en O(1):
    \begin{itemize}
        \item Pedirle informacion a MasAcumulador O(1)
        \item Pedirle informacion a MasCanjeador O(1)
    \end{itemize}
    \item rankingMillas en O(N log U )
    \begin{itemize}
        \item Tomar N veces el maximo del Heap N*O(1)
        \item Copiar los usuarios a un array O(N)
        \item Volver a ingresar N veces los usuarios al Heap O(N log U)
        \item Total: N*O(1) + O(N) + O(N log U) = O(N log U)
    \end{itemize}
    \item paresTransferidoresExclusivos en O(U)
    \begin{itemize}
        \item Recorrer el ABB elemento por elemento O(U)
        \item Chequear para cada usuario si esta en parTransferidorExclusivo O(1)
        \item Total : O(U)
    \end{itemize}
\end{itemize}
